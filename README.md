# Конструктор навчальних курсів

Застосунок для створення внутрішніх курсів: адміністратор (ви) крок за кроком
додає структуру, цілі, текст і тести, а співробітники читають і проходять курс,
бачачи свій прогрес. HR/адмін бачать зведений звіт.

**Рівні доступу — реальні**, перевіряються на сервері (у правилах Firestore),
а не просто прихованими кнопками:
- будь-хто, хто увійшов через Google — може проходити курси в каталозі;
- **адмін** (ви) — єдиний, хто може створювати/редагувати/видаляти курси;
- **HR** — бачить звіт про проходження, але не може створювати курси;
- звичайний працівник не бачить ні конструктор, ні HR-панель, і фізично
  не може прочитати чужий прогрес — навіть якщо спробує звернутись напряму
  до бази даних в обхід інтерфейсу.

Технології: React + Vite (фронтенд), Firebase Authentication (вхід через
Google) + Firestore (база даних), GitHub Pages (безкоштовний хостинг),
GitHub Actions (автодеплой при кожному пуші). Все — на безкоштовних тарифах.

---

## Крок 1. Створити проєкт Firebase

1. Зайдіть на https://console.firebase.google.com і натисніть **Add project** /
   **Створити проєкт**. Назвіть його, наприклад, `course-builder`.
2. Google Analytics можна вимкнути — він тут не потрібен.
3. Коли проєкт створено, у лівому меню відкрийте **Build → Authentication →
   Get started**. На вкладці **Sign-in method** увімкніть провайдер **Google**.
4. Відкрийте **Build → Firestore Database → Create database**. Оберіть режим
   **Production mode** та будь-який регіон (найближчий до України, наприклад
   `europe-west3`).
5. Зареєструйте веб-застосунок: на головній сторінці проєкту натисніть значок
   `</>` (Web app), задайте назву (напр. `web`), **не** вмикайте Firebase
   Hosting. Після реєстрації Firebase покаже об'єкт `firebaseConfig` —
   ці значення знадобляться нижче.

## Крок 2. Завантажити правила доступу у Firestore

1. У Firebase Console відкрийте **Firestore Database → Rules**.
2. Скопіюйте вміст файлу `firestore.rules` із цього проєкту й вставте замість
   того, що там є, натисніть **Publish**.

## Крок 2а. Дозволити вхід із домену GitHub Pages

Без цього кроку вхід через Google на задеплоєному сайті видасть помилку
`auth/unauthorized-domain` — Firebase дозволяє вхід лише з доменів у білому
списку.

1. **Authentication → Settings → Authorized domains → Add domain**.
2. Введіть `ВАШ_ЛОГІН.github.io` (без `https://` і без шляху після нього).
3. **Add**.

## Крок 3. Викласти код на GitHub

1. Створіть новий, **приватний** (щоб код бачили лише ви) репозиторій на
   GitHub, наприклад `course-builder`.
2. У теці цього проєкту виконайте:
   ```bash
   git init
   git add .
   git commit -m "Початкова версія конструктора курсів"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГІН/course-builder.git
   git push -u origin main
   ```
3. Якщо назвете репозиторій інакше, ніж `course-builder`, відкрийте
   `vite.config.js` і поправте рядок `base: '/course-builder/'` на
   `base: '/ВАША_НАЗВА/'`.

## Крок 4. Додати ключі Firebase як секрети GitHub

Ключі з `firebaseConfig` (Крок 1.5) не критично секретні (вони й так
потрапляють у код браузера), але зберігати їх у GitHub Secrets — акуратніша
практика і дозволяє білду підхопити їх автоматично.

1. У репозиторії на GitHub: **Settings → Secrets and variables → Actions →
   New repository secret**.
2. Додайте по одному кожен із цих секретів (значення — з `firebaseConfig`):
   - `VITE_FIREBASE_API_KEY`
   - `VITE_FIREBASE_AUTH_DOMAIN`
   - `VITE_FIREBASE_PROJECT_ID`
   - `VITE_FIREBASE_STORAGE_BUCKET`
   - `VITE_FIREBASE_MESSAGING_SENDER_ID`
   - `VITE_FIREBASE_APP_ID`

## Крок 5. Увімкнути GitHub Pages

1. У репозиторії: **Settings → Pages → Build and deployment → Source** →
   оберіть **GitHub Actions**.
2. Зробіть будь-який новий пуш у `main` (або відкрийте вкладку **Actions** і
   запустіть workflow `Deploy to GitHub Pages` вручну кнопкою **Run workflow**).
3. Через 1-2 хвилини сайт буде доступний за адресою
   `https://ВАШ_ЛОГІН.github.io/course-builder/`.

## Крок 6. Призначити собі права адміністратора

Ролі навмисно не редагуються з інтерфейсу (щоб ніхто не міг сам собі їх
видати) — тільки вручну, через консоль Firebase, і робите це саме ви:

1. Відкрийте сайт, натисніть **Увійти через Google** і увійдіть своїм
   акаунтом. Після першого входу застосунок автоматично створить ваш
   особистий профіль у базі.
2. У Firebase Console відкрийте **Authentication → Users** і скопіюйте
   значення **User UID** свого акаунта.
3. Відкрийте **Firestore Database → Data → Start collection**, назва
   колекції — `roles`. ID документа — вставте той самий UID. Додайте поля:
   - `isAdmin` (тип **boolean**) → `true`
   - `isHR` (тип **boolean**) → `true` (або `false`, якщо не потрібно)
4. Збережіть. Оновіть сторінку сайту (вийдіть і зайдіть знову, або просто
   перезавантажте) — з'явиться плитка «Конструктор курсів» і «HR-панель».

Щоб додати HR-фахівця: попросіть цю людину один раз увійти на сайт (тоді
з'явиться її UID у **Authentication → Users**), потім так само створіть їй
документ у `roles` з `isHR: true` (і `isAdmin: false` або взагалі без цього
поля).

## Локальний запуск (необов'язково, для перевірки перед деплоєм)

```bash
npm install
cp .env.example .env     # і вставте туди значення з firebaseConfig
npm run dev
```

## Обмеження, про які варто знати

- Увійти на сайт (і почати проходити курси як звичайний співробітник) може
  будь-хто з посиланням і Google-акаунтом — так само, як у Google Docs
  «за посиланням». Якщо потрібно жорстко обмежити вхід лише робочими
  поштами вашого домену (напр. `@vashacompania.com`), додайте в
  `firestore.rules` у кожне правило `isSignedIn()` додаткову перевірку
  `&& request.auth.token.email.matches('.*@vashacompania[.]com')`.
- Free-тариф Firebase (Spark) не має жорсткого ліміту користувачів для
  Authentication і Firestore на такі обсяги (десятки-сотні співробітників,
  кілька курсів) вистачить з великим запасом без переходу на платний план.
